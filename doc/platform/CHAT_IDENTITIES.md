# 群名与私聊昵称的持久索引

2026-10-23。名称属于显示资料，不是授权、会话或人设身份；群号和QQ号仍是稳定标识。无需先聊天才能取名。

## 名称从哪里来

OneBot连接后后台读取群列表和好友昵称，保存到SQLite；已知聊天缺名时分别补查群资料或非好友资料。成功资料按五分钟有效期后台更新，查询失败短暂退避。旧名称在离线、失败或QQ返回空名字时保留，不会因为一次查询失败清空。

工作台概览只同步读本地索引，不等待QQ。已有名称立即显示；尚未收录时先显示号码，独立名称请求等待有界的后台补全。若仍在处理，浏览器最多再补读两次，离开页面后停止；设置表单、人设草稿和语音弹窗不被重建。名称齐全的概览不再额外请求QQ资料接口。

群聊显示“群名 · 群号”，私聊显示“昵称 · QQ号”，本人另外标注“我的私聊”；相同名字也不会混淆不同对象。QQ无权返回某个非好友或历史群资料时仍显示号码，不伪造名称，也不要求先发生AI付费对话。

## 存储模型

专用文件为数据目录中的 `chat-identities.sqlite`，表 `chat_identities`：

| 列 | 含义 |
| --- | --- |
| `bot_id` | 机器人逻辑身份，当前为 primary |
| `chat_key` | 完整 group:群号 / private:QQ号 |
| `name` | 已验证格式的名称，最长200字符 |
| `source` | 群列表、好友列表、群资料、非好友资料或已有缓存种子 |
| `updated_at` | 名称最近实际改变的时间 |
| `last_checked_at` | 最近一次查询的发起时间 |
| `last_check_ok` | 本次检查是否取得有效名称，用于失败退避 |

主键为 `(bot_id, chat_key)`，同号群聊和私聊分开。SQLite有独立application_id、版本及完整性检查，WAL持久化，文件使用私有权限。旧请求的发起时间早于已保存记录时不能覆盖新结果。索引不保存消息正文、密钥、密码、好友备注或费用记录；不会把全部好友变成获授权聊天。

## 授权与故障

管理员的聊天列表动态合并已有聊天、当前群/私聊白名单及已启用的费用来源配置，因此新加白名单后不需要先发消息才能管理。同号群与私聊是两个对象。移除白名单后，只有仍有历史、其他授权记录或启用的费用配置时才继续显示；名称索引本身不会留下管理权限。

白名单是消息准入规则，并不是普通账号的管理授权。普通账号仍需本人QQ绑定或群管理身份验证/明确授权；平台新增某个白名单号码，不会将它开放给所有普通账号。

名称接口只返回当前账号有权管理的群和私聊，查询前和异步返回后均验证身份与范围；名称命中不能绕过原群管理身份验证。缓存损坏保留文件、名称接口报错或显示号码回退，原聊天引擎继续运行，不删库重建。后台查询限制并发和等待时间，退出时取消队列、停止定时器并等待有界任务结束后关闭库。

更新只涉及名称资料，不迁移或重建人设/会话，不更改模型、费用、语音或权限配置。测试及生产结果见工作记录。
