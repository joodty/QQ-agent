# 统一聊天能力与执行上下文

这是本 fork 的扩展设计，保留初始设计与验收依据；后续已接入独立账号、统一付费出口和旧档案主链，具体完成及部署状态以[当前交接](HANDOFF.md)和工作记录为准。下面的能力矩阵不代表任意模型、任意账号都已获授权使用所有功能。

## 不再以账号或 Key 拆分聊天引擎

目标调用链：可信 QQ 事件 → 解析完整聊天对象 → 核验资源权限 → 解析付款配置与人设版本 → 同一个 Agent/工具调度器 → 每次付费尝试的报价与预算 → 接收对象及版本复核 → 发送。

平台管理员和普通用户共用引擎；平台出资和用户出资共用引擎。模型不支持图片、搜索依赖不可用、某项操作未授权，可以产生明确的能力限制，但不能因为是用户 Key 就把整条链降成另一套纯文本实现。

| 能力 | 群聊 / 私聊 | 平台 / 用户出资 | 实际约束 |
| --- | --- | --- | --- |
| 文本、人设、记忆 | 同一实现 | 同一实现 | 当前对象与授权范围 |
| 看图、工具调用 | 同一实现 | 同一实现 | 模型兼容性、依赖与工具策略 |
| 费用、额度与降频 | 同一实现 | 同一实现 | 有效报价、当前付款人的明确预算 |
| 修改平台配置 | 不属于聊天能力等级 | 不由 Key 决定 | 平台管理员的后台权限 |
| 修改群设置 | 不提升平台角色 | 不由谁出钱直接授予 | 真实群身份或显式群授权 |

相同能力不等于所有账号都能执行服务器命令或读取他人资料。工具实现共用，操作权限逐次检查；LLM 提示词和前端隐藏按钮都不能替代后端检查。

## 上下文只携带引用，不替代授权

`src/conversation-context.js` 使用 AsyncLocalStorage 隔离并行任务，包含：

- `botId + conversationKey`：唯一聊天资源；同群多人管理仍是同一资源。
- `actorId`：服务器验证后的发起人标识，不要求每个群成员都有网页账号。
- `fundingRef`、`personaRef`：付款来源与人设的稳定 ID/版本，不放 API Key、角色开关或用户提交的原始声明。
- `requestId`：关联一次工作的标识，不能用来授予权限或替代每次供应商尝试的独立计费标识。

创建合法上下文只说明数据格式正确。未来消息入口必须先验证事件来源；凭据解析与最终发送还要重新核验授权、版本和资源。不能直接把浏览器 JSON 传给执行器。

`conversationResourceId()` 不包含操作者、付款人或人设，因此这些设置变化不会为同一群生成第二份共享额度。群聊和私聊即使号码相同仍分别隔离。

## 初始主链接入验收清单

1. 所有模型入口（含记忆、回复修复、重试和备选模型）都能携带正确的上下文，不能用缺失范围回退平台付款。
2. 用户配置只能选择明确授权的凭据与供应商；失败不能借用其他用户或平台配置。
3. 价格按实际端点、模型、缓存及时间解析；不完整报价按明确规则拒绝或保持功能关闭，不能显示一项额度却放任未知费用。
4. 预算在每次真实请求前预留，响应后结算；超时等未知费用先占额，不能靠重启或跨日清零。
5. 测试同一份消息经过两种费用来源时都保留工具、看图等适用能力，同时覆盖越权、撤销、并发、后台子任务及供应商失败。

独立上下文与预算单元测试不能证明主链集成；后续集成采用实际Agent调度加模拟供应商验证，具体证据在工作记录中分别保留。

## 发送任务与消息类型分别扩展

群发是发送任务能力，文字、语音、图片是消息类型；不要为每一种类型复制目标选择、权限判断、排队、进度、回执或幂等引擎。单发与群发也复用这套任务能力，只在目标数量和批量操作权限上区分。

任务统一接收 `message`，以 `type` 选择服务器内置的类型适配器。当前仅注册 `text`，由适配器独立校验、规范化正文，并调用现有文字出站能力；公共任务层统一处理当前账号、目标、请求指纹、调度、逐个目标结果及故障状态。客户端不能指定处理函数、任意消息段或绕过检查的远程资源。

未来语音适配器可复用任务引擎，但必须额外经过合成凭据、音色、字符报价、费用预算和当前聊天语音授权；图片也要有对应资源/模型及传输权限。人工文字不调用云服务，不等于其他消息类型可以免去费用检查。只有接入并验证了相应适配器，才能声明这种发送方式已经可用。
