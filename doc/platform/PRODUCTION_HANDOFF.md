# 旧账号入口与新聊天引擎的部署交接

当前生产执行结果等待维护者核验后补充。这里的地址、令牌和配置均是示例，不能直接替代私有部署资料。

## 运行边界

部署分为三个独立进程，复用已登录的 QQ/SnowLuma，不启动第二个 QQ 客户端。

| 进程 | 监听 | 职责 |
| --- | --- | --- |
| 旧 Bridge | 本机回环管理端口 | 原账号、Cookie、权限存储、QQ 本人验证及旧资料只读 |
| 新 QQ Agent | 本机回环聊天端口 | 唯一聊天引擎、人设档案、模型工具调用与新费用准入 |
| 管理网关 | 本机回环网关端口 | 核验旧账号管理员身份，代理新控制台；外层另有 HTTPS 入口 |

上游 QQ Agent 的控制台是本机单管理员工具。新网关每次请求都调用旧 Bridge 的 `/api/auth/status`，只接受仍有效的管理员 Cookie；普通账号和匿名用户不能访问新页面、脚本、API 或事件流。原账号数据库、密码派生值和已有会话不用迁移。普通账号目前仍使用旧入口，旧聊天设置在交接模式下只读；这不代表新引擎已有多人授权或 BYOK。

浏览器 Cookie、Authorization、旧机器令牌均不转交新引擎。网关重写内部 Host/Origin，并注入仅由服务器保存的新控制台随机令牌。新页面无需用户再输入该令牌。SSE 建连时鉴权，之后默认每五秒重新核验；账号服务最长三秒无响应即拒绝，已撤销的流通常在下一次检查关闭，配置上限约八秒。

## 账号与功能迁移矩阵

| 入口或能力 | 此阶段实际处理 |
| --- | --- |
| 原账号注册、登录、注销、修改密码 | 继续由原 Bridge 和原 SQLite 处理，不重建账号或已有会话 |
| 本人 QQ 验证码 | 原页面申请，私聊原机器人确认；属于非付费控制消息，新引擎忽略验证码 |
| 普通账号查看旧概览、已获授权的资料与历史统计 | 继续由旧路由按原权限提供；不会因此获得新控制台权限 |
| 普通账号修改旧人设、切角色、费用配置、Key、出资来源及额度 | 交接模式只读，旧写接口返回移交提示；尚未接到新引擎，不应当作保存后已生效 |
| 普通账号新增/扫码托管私人 QQ | 此阶段不开放，新产品方向为公共 QQ 服务群与私聊 |
| 新控制台、档案切换与新额度页面 | 仅原平台管理员，经网关访问；不是把所有普通用户升级为管理员 |
| 原 BYOK 与平台试用 | 原配置留存但新引擎尚未适配；未明确获平台出资授权的对象拒绝调用，不借用其他人的 Key |
| 费用与历史账本 | 原统计保留；新账本单独持久化，切换日已有花费作为一次性初值计入，不能把两边报表再次相加 |

普通账号的群管理、角色编辑和自带 Key 要在同一引擎完成授权与费用解析后逐项开放。本次网关没有移植整套多租户界面，也没有承诺旧工作台每一个按钮仍可写。

旧页面提交此类编辑时，HTTP 503 配合 `ENGINE_HANDOFF_MANAGEMENT_ONLY` 表示“当前入口只读，修改未保存”，不是保存成功或需要反复重试。应联系平台管理员在新控制台处理当前已开放的人设档案或额度；尚未移植的权限和 Key 功能需等待后续开放。账号登录、密码和本人 QQ 验证不受这类只读限制。

已导入聊天使用档案页所选的人设保留版本；当前只提供查看与切换，没有档案正文编辑接口。原生人设页面的正文修改只影响未使用导入档案的聊天，不能把保存成功理解为改写了导入档案。原生分会话编辑使用精确聊天键补丁，清除覆写会恢复全局继承，不需要开放整体配置替换。

## 私有配置示例

旧 Bridge 的原配置增加：

```json
{ "engineHandoff": { "managementOnly": true } }
```

该模式停止本实例会话映射、档案表和学习会话关联的旧 DSH 工作，不删除会话资料；不恢复 DSH 事件循环、自动社交与唤醒定时器。所有旧付费投递、BYOK 入站、主动消息、重试和 AI 出站由同一个守卫拒绝。登录、账号管理、只读资料与本人私聊验证码保留。`socialV2.paused=true` 只作用于部分旧 V2 路径，不能代替此开关。

网关使用独立私有 JSON 文件；示例令牌必须替换成服务器随机生成、至少 24 字符的值，并与新 `config.server.token` 完全一致：

```json
{
  "publicOrigin": "https://console.example.invalid:8445",
  "authOrigin": "http://127.0.0.1:3100",
  "targetOrigin": "http://127.0.0.1:3210",
  "consoleToken": "example-replace-with-private-random-value",
  "port": 3211
}
```

`publicOrigin` 必须是实际 HTTPS 源，包含非默认端口。认证与目标地址必须是固定本机 HTTP 源。私有配置放在源码与 Git 范围外，并限制文件权限。启动命令：

```text
node scripts/admin-gateway.mjs --config ABSOLUTE_PRIVATE_CONFIG.json
```

外层 HTTPS 反代必须保留浏览器的真实 Host（包括端口）及 Origin：`proxy_set_header Host $http_host;`，并标记 `X-Forwarded-Proto https`。网关核验公网源后才改写上游源，不信任客户端提交的用户身份或转发头。SSE 关闭缓冲并保留足够读超时。新服务与网关均只监听回环地址，禁止直接公开内部端口。

## 新引擎必须显式配置的项目

- OneBot HTTP/WS 使用保留 QQ 对应的准确端点及各自令牌；`snowluma.autoLaunch=false`。不运行 `setup`，不指向会自动遍历其他 QQ 令牌的共享运行目录，连接后核对实际 QQ 身份。
- `QQ_AGENT_DATA_DIR` 指向独立私有状态目录，采用 Node 24。历史通过离线导出与事务导入进入专用 SQLite，不复制账号或 QQ 登录态。导入 coverage 必须分别记录正文缺失、窗口截断、子会话和媒体引用。
- 旧 `dsh.baseUrl` 是会话/RPC 服务，不是 OpenAI 模型地址。只读取得 DSH 下游提供商的真实端点、Key 与精确模型 ID，再配置新 `api`、`providers`、`dshProviderKeys`。`providersSourceYaml` 不会在启动时自动导入；Anthropic 专用端点不能仅凭转换标记当作 OpenAI 兼容端点。
- 每群/私聊的付费范围、报价和限额按 [生产付费准入](PAID_CALL_GUARD.md) 配置，生产进程必须设置 `QQ_AGENT_REQUIRE_BUDGET=1`，缺少配置时也拒绝调用。未授权对象与用户 Key 不得静默改用平台 Key。新控制台公开接口只允许查询和修改受约束的额度；付款来源、报价、凭据和历史初始花费不接受浏览器整对象覆盖。
- 当前网关拒绝客户端启动/停止、整体重置、模块安装/发布、明文密钥查看、模型测试、视觉扫描、直接搜索、手工重试及记忆整理等入口。配置也不能重启 QQ、改控制台监听或启用未经此网关验收的后台付费循环。未列入正向清单的新接口默认拒绝。
- 联网搜索配置只允许显式关闭，不能通过切换 DeepSeek/自定义提供商重开付费旁路；配置中的 `__replace__`、非布尔后台开关和运行路径修改也拒绝，避免绕过局部字段检查。

## 切换与回退

1. 备份旧数据库及相关运行资料，确认备份可读；按完整 QQ 身份区分保留与停用的客户端。既有代理不在本任务的停止或改配范围。
2. 取得一致的旧资料与必要离线历史，先预览导出和导入 coverage；核对原人设、档案、当前选择及正文，原始记录不变。
3. 将旧 Bridge 置为管理交接模式，核验其状态以及旧会话停止结果，确认不再付费或回复。原登录与私聊验证码仍可用。
4. 启动独立新引擎和管理员网关，检查回环监听、实际 QQ 身份、限额范围、历史选择和公开入口权限。新旧引擎不能同时处理同一 QQ。
5. 验证匿名拒绝、普通账号拒绝、管理员可用、注销后新请求拒绝、旧 SSE 关闭，以及手机/桌面需要的基础页面。聊天验收使用明确允许的测试对象，区分本地模拟与实际消息。
6. 回退先停止新引擎并等待在途落账，再关闭新网关/公开入口；恢复旧交接开关和本次必要配置后才恢复旧聊天。保留新档案与账本，不拿旧备份覆盖切换后新增的记录。现有 headless 入口用 SIGINT 执行正常关闭，服务管理器应按此配置。
