# 独立账号平台与生产部署交接

更新日期：2026-10-23。本页当前方案已替代上一阶段“新聊天依赖旧 Bridge 登录”的过渡方案。独立平台已上线并完成生产验收，复用原 QQ / OneBot；旧 Bridge / DSH 已停止并禁用，身份、档案、凭据和费用保留均已核验。上一阶段事实保留为历史，不能据此恢复旧认证依赖。

## 当前进程与信任边界

| 进程或入口 | 职责 |
| --- | --- |
| 已登录的 QQ / OneBot | 沿用现有主客户端与真实身份，不新开托管 QQ，不改代理 |
| 新 QQ Agent（仅回环） | 唯一聊天引擎、独立账号/RBAC、QQ 绑定、群身份、档案、业务与预算 |
| 新网关（仅回环） | 直接验证同一 `platform.sqlite`；公开页面壳、同源账号 API、精确资源 API 和管理员高级入口 |
| 外层 HTTPS | 保留真实 Host/Origin，转发新网关；禁止公开内部端口 |
| 旧 Bridge / DSH | 已停止并禁用；一致性冷备作为只读迁移来源和回退资料，不作为新平台认证或聊天的运行依赖 |

浏览器直接在新站登录，不再先去另一端口登录。旧账号 ID、scrypt 验证材料、密码版本、角色、停用状态、精确授权、QQ 绑定和有效会话哈希经一次性导入保留；不重置密码、不延长 Cookie 到期时间。Cookie 名继续为 `qq_console_session`，新发 Cookie 使用 HttpOnly、SameSite=Strict 和 HTTPS Secure。

网页角色只影响展示。所有账号与资源 API 从本地 SQLite 重新验证会话和授权，不相信浏览器提交的 role、付款人或 Key 引用。普通注册默认无群权限；绑定本人 QQ 才自动获得本人私聊，群管理需机器人确实在群内，且 OneBot 返回已绑定 QQ 为群主或管理员。同群是一个资源，可有多个管理者。

自动群身份证据有效期为两分钟，可信群事件即时失效，后台续证；未续证的权限到期拒绝。显式管理员委托与自动群证据分开。续证、在途请求和 QQ 发送通过精确账号/资源权限版本校验，普通登录不会使无关群的在途回复失效。

## 页面与 API

- `/` 跳转 `/workspace.html`；登录、注册、工作台静态壳和 `/help.html` 可公开，数据仍鉴权。
- 工作台围绕聊天与人设、费用与额度、自己的 API 配置、本人 QQ 和密码组织。管理员另有平台默认规则、账号授权及 `/console.html` 高级入口。
- `/api/auth/*` 在新网关或新应用内本地处理。`/api/platform/*` 保留同源 Cookie、Host、Origin并在应用再次校验身份；群申请必须转到应用现有 OneBot 核验器，网关不再建第二个客户端。
- 原生完整配置、运行记录、模型原始 JSON 和 SSE 仅管理员可访问。网关向内部注入私有控制台令牌，浏览器不接收该值；普通账号不能直接获取全局配置、其他用户 Key 或无授权聊天。
- 管理员高级页面仍使用正向 API 清单；客户端/进程启动、安装发布、明文秘密、未受预算保护的付费搜索及系统测试入口继续拒绝。注册账号不会创建 QQ 客户端或后台进程。
- 原生运行记录默认详情和 SSE 不带模型 raw，完整 JSON 仅管理员明确点击后惰性获取。运行记录是一次 Agent 工作，不是长期人设档案。

## 私有部署配置

新应用的私有配置启用 `platform`，或通过 `QQ_AGENT_PUBLIC_ORIGIN` 指定唯一公开源。`platform.file` 默认位于 `QQ_AGENT_DATA_DIR/platform.sqlite`。网关读取同一文件，**不再支持 `authOrigin`**。

```json
{
  "publicOrigin": "https://console.example.invalid:8445",
  "platformFile": "/srv/example-private/platform.sqlite",
  "targetOrigin": "http://127.0.0.1:3210",
  "consoleToken": "example-replace-with-private-random-value",
  "port": 3211
}
```

以上均是占位示例。私有随机令牌至少 24 字符，并与新应用 `server.token` 一致；私有配置、数据和加密主密钥放 Git 范围外。网关启动：

```text
node scripts/admin-gateway.mjs --config ABSOLUTE_PRIVATE_CONFIG.json
```

外层反代保留 `Host $http_host` 与原始 Origin，设置 `X-Forwarded-Proto https`；SSE 禁止缓冲。公网写操作校验显式配置的 HTTPS 源，网关仅接受回环反代请求。原生内部请求改写为回环源且去掉用户 Cookie；普通资源请求保留 Cookie 供应用复核。Native SSE 每五秒复核本地账号，注销、禁用或撤销后关闭。

若使用 systemd 的 `ProtectSystem=strict`，应用和网关都需对独立数据目录授予精确 `ReadWritePaths`：账号登录、注销及 SQLite WAL 写入不能依赖旧服务的目录权限。仅开放实际数据路径，不取消整体文件系统保护。

使用独立静态服务账号，不复用由旧服务 `DynamicUser` 临时提供的身份。停止旧服务后，该账号仍须可被系统解析，并对新平台数据具有所需权限；去除 HTTP 依赖也要一并核对运行身份与文件归属。

OneBot 使用保留 QQ 的准确 HTTP/WS 端点与分别匹配的令牌；`snowluma.autoLaunch=false`，不运行 `setup`，不设置会自动遍历其它客户端的共享目录。模型端点必须是批准且有完整报价的提供商，不把 DSH RPC 地址当作模型 API。生产要求 `QQ_AGENT_REQUIRE_BUDGET=1`。

## 一次性账号与业务导入

在一致性私有副本上先执行账号预览：

```text
node scripts/import-platform-accounts.mjs --source-sqlite ABSOLUTE_OLD_SNAPSHOT.sqlite --target ABSOLUTE_NEW_PLATFORM.sqlite
```

预览只读源数据，不建目标库，不创建账号、会话或绑定。加 `--apply` 才原子写入空目标库；`--source-id` 指定可追溯来源，`--bundle` 可使用私有规范文件。`--write-bundle` 仅在显式指定时以不覆盖方式输出私有材料，包含密码/会话哈希，不能放公开仓库。工具 stdout 只输出计数。

保留原账号稳定 ID、密码派生、passwordVersion、disabled、角色、全部认证会话、精确 bot+群/私聊授权、本人 QQ 和待验证挑战；委托展开为显式资源授权。过期 Cookie 不会因迁移复活。相同来源重复导入幂等，不覆盖新账号或恢复迁入后已撤销会话；冲突来源或内容拒绝。目标错误数据库身份、缺表或未知 schema 拒绝接管。

迁移工具是长期保留的部署能力，默认预览和同来源幂等规则适用于其他部署者；完成一次真实导入后不删除这些工具。旧 DSH 特有执行器和多客户端托管不会因保全数据自动恢复。

用户凭据、出资、平台体验和历史费用通过 `scripts/import-platform-business.mjs` 单独导入。旧密文仅在私有迁移边界解密并按新所有者 AAD 重新加密；密钥不进入账号库、通用请求上下文、API 响应或公开迁移包。历史用量有独立来源与去重身份，不能和切换日 seed 再次相加。旧档案导入与 coverage 仍见 [导入指南](LEGACY_IMPORT.md)。表及关系见 [数据模型](PLATFORM_MODEL.md)。

`scripts/export-platform-legacy-business.mjs --bridge-root ABSOLUTE_SNAPSHOT` 默认只读预览。导出私有规范包另加 `--usage-json ABSOLUTE_DAILY_EXPORT.json --source-id SAFE_ID --output ABSOLUTE_PRIVATE_BUNDLE.json`，主密钥仅使用该快照下的精确 `state/tenant-key`，也可通过 `--master-key` 显式指定。不会遍历秘密文件或新建旧主密钥。

费用输入必须由原 token-ledger 的去重 `daily` API 离线生成，不接受把 JSONL 行直接求和。格式为 `{format:'qq-bridge-usage-export',version:1,basis:'legacy-token-ledger-daily',coverage:{currency:'CNY',droppedLines:0,trialComplete:true},usage:[规范记录],trialInitialSpent:{日期:人民币金额}}`。历史用量保原日期、金额和稳定 ID；平台体验初值按权威旧 trial 总额的每日下限与独立 trial ledger 取较大值并向上微元。未决费用、活动/到期未解决预留或健康异常会阻止写出，不能伪装成已结算并在午夜清掉。

同一实际来源重复导入必须固定 `sourceId`。历史用量只补统计，独立 trial 初值只补平台体验总账，不能代替个人或主聊天当天的准入余额。当前没有通用当日正余额补差接口：必须证明切换日旧 main/trial 的每个对象和 trial 总额均为零，或先完成经过验证的幂等余额转移；不能只看历史导入成功就放行，更不能改日期或重写已有 immutable seed 来通过。私有离线助手可显式读取审计过的旧账本纯函数；新运行时代码不引用旧源码。

## 切换与回退

1. 核对备份、当前 QQ 身份和受保护进程，记录源账号/会话/授权/费用/档案摘要。仅唯一部署执行者操作生产；代理不在本次改配范围。
2. 使用一致性副本先预览账号与业务，再导入到独立新库，逐值核对身份、密码验证材料、会话、授权、绑定、加密归属与费用。保持原 QQ 与 OneBot。
3. 停止旧聊天和旧认证写入后做最终一致导入，启动新平台与网关，确认无旧 Bridge / DSH HTTP 依赖；不能让两边同时改账号或回复同一 QQ。
4. 实测原账号直接在新站登录、匿名与普通权限、普通空资源、本人绑定、可信群核验、跨群拒绝、版本编辑与应用、用户 Key 失败不回退、费用准入、Cookie 撤销和 SSE。只读浏览器验证桌面/手机布局，区分模拟和真机。
5. 新平台独立验证通过后再退役旧管理/聊天服务；保留旧数据与备份，不恢复私人 QQ 托管，不因退役误停共享 QQ、OneBot 或代理。
6. 回退先停止新请求并正常等待在途落账，保存新 SQLite 和加密主密钥。切换后新增的账号、档案、Key、授权与账本不能被旧备份覆盖；恢复旧写入前必须规划反向数据同步，不能盲目打开两个写入者。
