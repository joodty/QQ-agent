# 从 QQ Bridge 平台迁到 QQ Agent

更新日期：2026-10-23。旧项目的账号、授权、人设档案、预算和验证经验继续保留。新 QQ Agent 已独立承载账号与业务并完成生产验收，旧 Bridge / DSH 已停止并禁用，旧源码和数据库作为迁移来源与冷备；平台/用户 Key 使用同一套聊天引擎。原身份、档案、凭据和费用已核验保留，公开验收范围见生产交接。

本轮检查的上游基线为 `fdfd325e148d91845a0aeea3dfdff4cf92fc61a1`。开发仓库为 [joodty/QQ-agent](https://github.com/joodty/QQ-agent)，迁移开发分支为 `codex/group-management`，保留 `upstream` 跟踪原作者。上游与第三方组件的许可、署名继续适用。

## 先区分现有能力和迁移目标

- **旧平台已有**：账号密码与 Cookie、本人 QQ 验证、指定群/私聊授权、人设版本与会话档案、SQLite 管理状态、估算费用与每日预算、自带 Key 配置及独立 QQ 接入。
- **QQ Agent 上游已有**：OneBot 接入、共用模型调用与工具链、模型/供应商目录、图片与搜索等能力、群/私聊存档、记忆、用量报表，以及 `personaForChat` 的按会话人设覆盖。具体功能还受模型、插件、配置与接口状态约束。
- **新独立平台代码**：本地账号/注册/密码/Cookie、精确资源 RBAC、可信本人 QQ 与群身份、普通账号同站工作台、版本化人设显式应用、加密自带 Key、出资来源、试用双层限额、历史费用与共用 Agent 费用准入已落盘；主链与页面验收由集成测试证明，部署状态见 [工作记录](WORK_LOG.md)。
- **旧资料导入进展**：只读离线导出、coverage 预览/事务导入、原身份保留、按档案的消息/记忆和 A → B → A 续聊已实现。生产导入四个人设、八个档案和六个当前选择；导入时可证明 QQ 窗口消息为 386 条，仍属部分窗口，不能称为完整群历史。来源与验证边界见 [生产交接](PRODUCTION_HANDOFF.md) 和 [导入指南](LEGACY_IMPORT.md)。
- **上一阶段过渡**：曾由旧 Bridge 登录认证新管理员控制台、旧普通账号页面只读。该模式是已上线的历史阶段，本轮独立迁移后禁止恢复 `authOrigin` 或跨端口登录依赖。
- **保真导入**：新增账号与业务私有导入工具，保留稳定账号 ID、密码哈希/版本/停用/角色、认证会话、精确 scope、绑定、凭据归属和用量来源。默认预览不写；反复同源导入不会复活撤权/会话或覆盖新运行数据。工具作为可重复部署能力长期保留，不能导完就删除。
- **持续限制**：未受预算保护的付费搜索、任意扩展安装和系统控制继续拒绝。私人 QQ 托管、多客户端编排、旧 DSH 特有执行器不恢复；相关数据保全不等于运行能力直接照搬。TTS 另行设计。

不得把旧平台已经实现的功能，或本文件里的设计，直接列成新平台已完成的功能。当前上游有用量统计，其配置还明确移除了历史 `budget` 容器；统计金额不能代替预算准入。

QQ Agent 已有按群/私聊人设覆盖，应先扩展这一处。旧兼容配置可按纯数字查找，新平台内部必须使用包含对象类型的完整身份，避免群号和私聊号相同时发生覆盖。

## 必须适配的部分

### 使用同一聊天引擎的持续契约

所有适用的用户与费用来源都走同一条模型、工具、记忆和消息处理链路。调用时明确携带机器人身份、群/私聊身份、当前人设版本、资源授权、费用来源与预算策略；密钥只在可信调用边界解析，不放入通用上下文或日志。

平台管理员能管理平台默认项，普通账号只能操作已授权资源。平台角色不决定 AI 是否能看图、搜索或使用已允许的工具。Key 决定谁付费，不决定走“完整机器人”还是另一条纯文本机器人。模型不支持某个模态、工具未启用或资源未授权时，应返回具体原因。

通用能力契约与调用上下文见 [能力契约](CAPABILITY_CONTRACT.md)。通用不等于所有人有所有权限：本地文件、命令、跨群发信等操作仍须独立限制。

### 公共机器人下的群管理

同一机器人和群号只对应一条群记录；一个用户可管理多个群，一个群可有多个管理者。进群、取得平台管理权、启用付费聊天是三个独立状态。

用户先验证本人 QQ，再通过可信群事件及群身份查询验证其群主/群管理员身份；普通群成员只能获得明确的协作授权。先填写群号的人不能永久占有该群。已有群应关联同一管理页面，并发申请也不能生成重复群配置。

一群只有一套当前人设、当前付费来源和共享每日额度。出资人明确允许使用本人 Key 及消费上限，其他管理者不能擅自提高其支出。群管理员身份变化、退出群或撤销授权后，异步操作结束前仍须重新校验。

### 一套费用准入覆盖全部付费路径

群与私聊使用同一预算服务；管理员私聊仍是私聊。记忆整理、工具追加模型轮次、重试、备选模型以及后台任务都必须有明确归属；没有群归属的任务使用独立且受限的平台预算，不能借空上下文绕过检查。

每次真实付费尝试都经过“确认归属与价格 → 原子预留 → 发出请求 → 结算或标记未知”的共同边界。同一尝试重复回报不得重复结算，不同重试不能当作一次免费尝试。跨供应商时按实际模型、价格与用量口径结算，旧平台的固定模型单价不能直接沿用。

默认值是群/私聊每日 ¥1，可在权限范围内配置；接近 80% 时减少输出和参与，额度不足时拒绝新的付费调用。这是估算与在途预留策略，不保证供应商实际账单严格等于本地金额。未知用量、请求已发出后超时或进程重启，不应直接退款释放全部额度。新平台/用户 Key 路径均需通过真实隔离 HTTP 主链验证，不能只凭预算内核测试宣称接线完成。

### 从个人桌面信任边界迁到多人平台

上游允许本机操作者配置模型端点和安装扩展，不等于这些操作可直接开放给网页普通用户。多供应商需要 Provider 适配、能力声明、出站访问策略和费用归属。用户 Key 不能随任意 `baseURL`、跨供应商重试或全局账号池泄露；改 Key 也不能绕过资源授权。多人平台不能把上传任意 JavaScript 等同于普通设置。

## 本阶段不迁入的内容

| 内容 | 原因与处理 |
| --- | --- |
| 自助托管私人 QQ、容器名额和扫码编排 | 当前主线收敛为公共机器人和独立群管理；旧实现与运行资料保留，不因重开仓库停止或删除既有实例 |
| 每个用户再复制 QQ、Bridge 和 DSH | 不把账号注册等同于启动一套运行环境；容量和接入路线需单独评估 |
| DSH 特有工具协议和会话恢复实现 | 新底座直接使用 QQ Agent 引擎；旧会话 ID 只能保留为来源引用，不能当成新引擎可继续使用的 ID |
| 旧 `tenant-chat` 纯文本支线 | 不复制“用户自带 Key 所以能力更少”的实现；将费用策略接到完整引擎 |
| 旧页面上的机器人层级与所有权文案 | 普通用户围绕群/私聊操作；平台角色、群管理权限和出资身份分别表达 |
| 生产配置、数据库、模型凭据和运行截图 | 只进入授权的私有迁移过程，任何公共提交和测试夹具均不包含这些资料 |

旧代码继续作为历史和数据来源保留；本轮独立平台上线后，旧管理/聊天服务已退役，数据库和资料冷备保留。退役不构成删除旧分支、表、会话或账本的理由。后加私人 QQ 托管仍停用，不能把旧数据保全理解为重新启用其运行服务。

## 真实数据迁移前的要求

1. 明确旧数据权威来源并做一致性备份；旧 SQLite 与配套加密主密钥按实际关系保存，禁止用冻结 JSON 覆盖后续数据。
2. 保留账号稳定 ID、密码验证材料、QQ 验证关系和精确授权。登录 Cookie 能否继续使用须验证签名和撤销语义；不兼容时安排显式重新登录，不能为方便重建账号或重置密码。
3. 保留人设 ID、正文版本、历史作者、当前应用关系、会话档案和原始来源引用。将 DSH 的后端 ID 与新引擎会话 ID 分列，不伪造可继续关系；长期记忆与历史消息兼容情况另行验证。
4. 保留已结算用量、价格口径、在途预留与待核对费用；导入器必须幂等且能给出未映射项。迁移不得通过清账本、改日期或创建新身份恢复额度。
5. 在脱敏导出或隔离副本上执行干跑，核对行数、引用、金额、人设 A → B → A 和多人授权，再验证回滚方案。真实运行切换以单独部署记录为准。

会话档案得以保留，不保证供应商缓存永久命中。不能为“省钱”承诺保留某个 ID 就一定维持原缓存费用。
