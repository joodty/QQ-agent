# 平台手动消息与群发

“我的聊天 → 选择群或私聊 → 聊天记录”用于查看当前人设档案，也提供手动发送。选择文字时直接发送正文；选择语音时，将编辑的正文按本条指定音色合成，再以当前机器人QQ身份发送，成功后保留在对应聊天历史。两种形式都不需要调用聊天模型；语音需要腾讯语音服务并会产生用量。

管理员在“平台管理 → 群发消息”选择目标，核对预览后明确发送。群聊和私聊分别显示，默认不选中任何目标；每批最多20个目标、文字最多2000字符，返回每个目标的结果。普通账号没有群发权限，但可以给自己有权管理且机器人允许发送的聊天单独发消息。

管理授权、机器人消息准入、QQ连接/退群状态和发送限频分别校验。人工文字无需开启模型付款来源；它不能开启AI调用，也不能绕过机器人黑白名单。人工语音沿用现有语音服务、聊天开关、资助、付款来源和统一费用守卫，缺少设置时给出原因，不自动开通或借用别人的额度。模型与工具保持原有付费和发送规则，不能通过模型参数启用人工发送路径。

同一请求的重复提交复用发送回执；使用相同请求标识修改正文或目标会被拒绝。结果不明时显示待确认，不自动重发，刷新或重启服务也不能将已经受理的请求重新执行。发送成功与消息落盘是不同状态：QQ已经受理后无法通过撤权或切换档案撤回；历史应写入发起时捕获的原档案。

浏览器发送草稿与当前账号、聊天分别绑定，迟到结果不回填其他聊天或账号；离开页面不会自动发消息。平台测试使用模拟QQ，生产验收只读目标和回执元数据及校验拒绝路径，不向真实群或用户发送测试消息。

API为 `GET /api/platform/messages/targets`、`POST /api/platform/messages/send`、`POST /api/platform/messages/broadcast` 和 `GET /api/platform/messages/result?requestId=...`。发送必须带请求标识；普通单发带完整 `chatKey`，群发带不重复的 `chatKeys`。消息使用 `message:{type:'text',text:'正文'}`；兼容旧 `text` 参数，二者不能同时传入，规范化后计算同一幂等指纹。目录只包含当前有发送权限的已知对象，不枚举所有QQ好友来扩大授权。响应为私有no-store。

发送任务统一负责目标、授权、排队、回执和防重复；消息类型适配器负责该类型内容校验与实际传输。文字和语音已接入同一任务，图片尚未实现，未知类型明确拒绝。人工语音不会按自动回复概率抽样，也不会修改当前聊天或平台的默认音色。

## 指定文字与音色发送语音

单发在当前聊天的“聊天记录”页选择“语音”；群发在“平台管理 → 群发消息”选择“语音”，勾选目标并编辑正文、选择音色。音色列表复用现有目录，选择只影响这条消息。先核算，再核对每个目标的字符数、上限、估算费用及受阻原因，最后明确确认发送；修改正文、目标或音色会使旧核算失效。

语音正文受每个目标的有效上限约束，平台绝对上限150字符，默认设置可能更低。沿用目标已保存的语速和音量，不使用SSML。按目标分别合成、预留及记录费用，不承诺多目标共用一次合成或只计一次费用。报价是目录标价估算，资源包实际抵扣与供应商账单仍以腾讯云为准。

`POST /api/platform/messages/quote` 只核算和检查权限/额度，不调用腾讯合成或QQ发送，不创建发送任务。语音消息使用 `message:{type:'speech',text:'正文',voiceType:音色编号}`，可选语速/音量；确认发送携带核算返回的 `speechPolicyVersions`。服务器将核算绑定到正文、指定音色、价格和目标有效策略，发生变化需重新核算；免费核算不保证之后并发调用仍有额度，发送时逐目标再检查。

任务先持久化，云请求前再保存合成阶段，QQ发送前保存发送阶段。语音合成与QQ送达分别显示：合成成功而QQ未送达仍可能已产生费用；云端或QQ结果不明时保留待核对，不自动重新合成或重发。刷新、重复提交相同请求及重启均不能绕开这一点。消息送达后落入发起时捕获的原人设档案。

回执保存在独立的 `manual-messages.sqlite`：

| 表 | 关键列与用途 |
| --- | --- |
| `manual_requests` | 主键 `(user_id, request_id)`；保存正文/目标的摘要、单发或群发类型、创建时间，不重复保存正文 |
| `manual_results` | 主键 `(user_id, request_id, ordinal)`，外键指向请求；保存完整聊天键、状态、QQ消息编号、错误及历史落盘标记；schema 2 增加消息类型、处理阶段、合成结果和估算费用 |

库有独立application_id、版本、私有权限及完整性校验。schema 1 升级到2保留原文字回执；启动时在途发送转待核对，尚未发送的排队项结束为未发送，不恢复执行。回执库损坏保留文件并停用人工接口，现有聊天引擎继续运行。代码回退不能通过覆盖数据库降级：旧版本可能暂时关闭人工接口，现有聊天和回执数据仍须保留。具体测试与部署证据见工作记录。
