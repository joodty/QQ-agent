# 平台手动消息与群发

“我的聊天 → 选择群或私聊 → 聊天记录”用于查看当前人设档案，也提供手动文字发送。消息以当前机器人QQ身份发送，成功后保留在对应聊天历史；不会为这段文字调用模型或合成语音。

管理员在“平台管理 → 群发消息”选择目标，核对预览后明确发送。群聊和私聊分别显示，默认不选中任何目标；每批最多20个目标、文字最多2000字符，返回每个目标的结果。普通账号没有群发权限，但可以给自己有权管理且机器人允许发送的聊天单独发消息。

管理授权、机器人消息准入、QQ连接/退群状态和发送限频分别校验。人工发送无需开启模型付款来源；它不能开启AI调用，也不能绕过机器人黑白名单。模型与工具保持原有付费和发送规则，不能通过模型参数启用人工发送路径。

同一请求的重复提交复用发送回执；使用相同请求标识修改正文或目标会被拒绝。结果不明时显示待确认，不自动重发，刷新或重启服务也不能将已经受理的请求重新执行。发送成功与消息落盘是不同状态：QQ已经受理后无法通过撤权或切换档案撤回；历史应写入发起时捕获的原档案。

浏览器发送草稿与当前账号、聊天分别绑定，迟到结果不回填其他聊天或账号；离开页面不会自动发消息。平台测试使用模拟QQ，生产验收只读目标和回执元数据及校验拒绝路径，不向真实群或用户发送测试消息。

API为 `GET /api/platform/messages/targets`、`POST /api/platform/messages/send`、`POST /api/platform/messages/broadcast` 和 `GET /api/platform/messages/result?requestId=...`。发送必须带请求标识；普通单发带完整 `chatKey`，群发带不重复的 `chatKeys`。消息使用 `message:{type:'text',text:'正文'}`；兼容旧 `text` 参数，二者不能同时传入，规范化后计算同一幂等指纹。目录只包含当前有发送权限的已知对象，不枚举所有QQ好友来扩大授权。响应为私有no-store。

发送任务统一负责目标、授权、排队、回执和防重复；消息类型适配器负责该类型内容校验与实际传输。当前只注册文字适配器，语音群发/图片群发尚未实现，未知类型明确拒绝。未来语音要接入自己的费用、音色和资源授权，不能复用人工文字的免云调用特性绕过费用检查。

回执保存在独立的 `manual-messages.sqlite`：

| 表 | 关键列与用途 |
| --- | --- |
| `manual_requests` | 主键 `(user_id, request_id)`；保存正文/目标的摘要、单发或群发类型、创建时间，不重复保存正文 |
| `manual_results` | 主键 `(user_id, request_id, ordinal)`，外键指向请求；保存完整聊天键、状态、QQ消息编号、错误及历史落盘标记 |

库有独立application_id、版本、私有权限及完整性校验。启动时在途发送转待核对，尚未发送的排队项结束为未发送，不恢复执行。回执库损坏保留文件并停用人工接口，现有聊天引擎继续运行。具体测试与部署证据见工作记录。
