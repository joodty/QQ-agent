# 群管理扩展工作记录

日期使用 Asia/Shanghai。记录需求、实际代码、验证、部署和未完成项；不放真实服务器、QQ、密钥或运行数据。

## 2026-10-22：旧档案导入与按人设续聊

- 需求：保留旧系统的人设、原 ID/版本、会话档案及能读取到的聊天历史，切回旧人设后继续；通常正式导入一次，但工具支持预览、重试与补导。
- 导出：只读提取旧 SQLite 权威人设/档案和必要运行 JSON，WAL 副本在隔离目录读取；不读账号和 Key 业务表，不连接 DSH。支持事先取得的官方离线 JSONL/SessionRawArtifact，保留子会话原事件；coverage 单列正文缺失、有界 QQ 窗口、DSH 缺失/截断/投影缺口。不会将 recent 200 条或旧 200 字正文说成完整群历史。
- 导入：canonical bundle v1 → 独立 `conversation-archives.sqlite` schema 2。原身份、正文、版本来源、档案关系、旧 DSH ID、原始事件与当前选择可追溯；事务/CAS、幂等和严格前缀补导不覆盖运行新消息或新选择。封存、缺失与已删除人设保留为不可续聊；允许部分来源不绕过此检查。
- 运行：ChatStore、Memory、personaForChat 和同一个 Agent 主链按档案取上下文。新增本机“人设档案”页面与受原访问/来源校验保护的列表/切换 API。选择版本防 A → B → A 旧任务复活，取消等待、在途模型和记忆整理，全部发送类型延迟后复核；已成功发给 QQ 的消息仍落到原档案，停机等待落账后关闭数据库。
- 保留边界：不通过消息窗口上限自动裁剪导入历史；历史事件不重放为工具、审批或未读消息。旧内部控制/替换投影/子会话不自动作为主会话续聊资料；安全纯文本只按有限窗口进入提示词。媒体目前保留引用，不复制二进制；账号、授权、费用账本和供应商配置仍属其他迁移阶段。
- 验证：`npm run test:archives` 67/67（持久层 24、源导出 20、实际 HTTP/WS 主链 15 个子场景加 1 个总套、CLI/页面与上下文 7），`npm run test:platform` 35/35；均无失败、跳过或 todo。覆盖源 DB/WAL/SHM hash 不变、250 条完整离线文本、缺失与 inactive、事务回滚、两个进程 CAS、重启、真实提示词 A/B/A、同号群私、重试退避与记忆取消、五类发送及已发归属。页面交互使用 jsdom，未宣称实体浏览器或手机实测。
- 上游回归：26 个普通与 5 个覆盖脚本独立执行，29 个退出为 0，仍为原有两处失败（QQ 安装组件缺失时的 CLIENT_BUILD 断言、官网安装包文件名正则），无新增失败。覆盖 HTTP 原套件 85/92 条声明路由，档案 API 另由新运行测试覆盖；jsdom 扫描 740 个交互元素、14/16 弹窗实际生成。安装归档哈希、SnowLuma 对齐/build、无扩展工具与无按天数据等条件跳过不列为实测通过。
- 性能：虚构 10,000 消息与 4,000 惰性事件、约 3.67 MB bundle，选择元数据 30 次约 4.6 ms，目标消息读取 30 次约 793 ms；选择查询不扫描原始全文。写入仍完整校验，大库写入成本随总量增长，未承诺无限规模性能。
- 环境与发布：服务端档案使用 Node 24；package 与 lockfile 仅同步根 engines，不改变依赖。默认打包排除本地资料及 SQLite。代码、指南与交接作为本次提交推送当前公开开发分支；实际远端以包含本记录的提交为准。没有执行生产导入、部署、QQ 登录、付费模型请求或代理调整。

操作步骤见 [旧档案导入指南](LEGACY_IMPORT.md)。第一次真实迁移前仍需取得一致的旧数据副本、必要 DSH 离线导出并核对 coverage；本地模拟通过不证明未知生产资料已完整导入。
